# 전체 720 리소스 검수

2026-10-02, `codex/animation-720-quality`. 기본 위젯에 등록된 62개 영상과 846개 PNG를 원시 이미지에서 다시 키잉·정합했다. 기존 512 완성 PNG를 일괄 확대하지 않았다. 동작·표정·의상·소품·카메라 배율·FPS·holds·repeats·상태별 속도를 유지했다. 기존 62개 영상 및 846개 PNG의 해시가 보존된다.

## 검증

- `tools/audit_hd720.py`: 전체 720×720 RGBA PNG, 순서·개수·가장자리 투명도, VP9 알파 영상, 전체 디코딩 tick과 영상 길이, 기존 리소스 해시 통과. 최종 녹색 테두리 보정 이후 안정된 파일에서 다시 실행했다.
- 육안 검수: root 기본 13개와 담당자 춤·반응 22개, 특수 14개, 파티시에 13개의 전체 프레임 비교 시트를 실제로 열어 확인했다. 고해상도 원본이 있는 얼굴·가운·필기 디테일 개선, 기존 동작과 공통 접합점 보존을 확인했다. boxing의 7/8번 인덱스는 앞서 승인된 정면 호흡 동작을 유지한다.
- `node tools/widget_check.js`: 렌더링 빈도, 16개 반응, 춤 루프, 연금술 3개 결말, 무기한 유지, 숨김/복귀, 캐시 상한, 큐·전환·워치독 등 13항목 통과.
- `node tools/widget_hd720_check.js`: 기본 경로와 등록된 62개 클립의 실제 `playClip` 완료, 720 디코딩, 불투명 본체·투명 코너와 합성, 길이 통과. 최종 파티시에 테두리 수정 후 `--prefix pastry1_`로 해당 13개 클립을 다시 통과했다.
- 화면 1280×720 / 720×1280 DPR1 및 1280×720 DPR2에서 합성 720², 320×640 DPR1에서 320²를 확인했다. 실제 인앱 브라우저 가로 화면에서도 정사각형 영상이 중앙에 표시된다. 이전 직사각형 합성에서 먼저 축소되던 화질 손실을 없앴다.
- `python tools/deploy_pages.py --require-reviewed`: 전체 영상 해시·검수 상태를 확인해 720 배포본을 생성한다. 원격 게시와 별개다.

## 보정과 한계

파티시에의 음식 녹색을 보호하면서 테두리의 녹색 보간 번짐을 제거했다. 화학 무지개 결말 frame12는 액체 보호 영역을 플라스크에 한정해 머리 사이에 남은 배경을 제거했다. 춤 투명 원본에 섞인 이웃 셀의 작은 파편을 제거했다. 원시 이미지 및 이전 512 결과는 수정하지 않았다.

1254px 개별 원본과 1024px 필기 원본은 선명도가 좋아진다. 627px 시트 셀은 그 범위의 디테일을 살리고, 약314px OBS·연금술 셀은 본래 해상도 한계가 남는다. 720 출력이 부족한 원본 디테일을 새로 생성하는 것은 아니다. 프레임별 원시 파일·셀 좌표·해상도 한계와 변환은 네 담당자 JSON에 기록한다.

검증 결과는 `hd720_manifest.json`의 현재 PNG·영상 해시에 연결된다. 재생성하면 감사 도구가 상태를 `audited`로 초기화하므로 다시 육안·런타임 검수한 뒤 `reviewed`로 기록한다. 이전 검수 승인만으로 새 파일을 승인하지 않는다.
